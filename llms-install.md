# llms-install.md

**English:** machine-facing install guide for `horoshop-mcp`. If you are an AI agent setting this
MCP server up for a user, follow the steps below literally. Instructions are in Ukrainian.

---

Це інструкція для ШІ-агента, який встановлює `horoshop-mcp` користувачу. Виконуй кроки по
порядку. Якщо чогось бракує — зупинись і спитай, не вигадуй.

## Що встановлюємо

MCP-сервер для [Horoshop](https://horoshop.ua): замовлення, каталог, розділи, покупці,
комплекти товарів, довідники доставки й оплати, вебхуки. Тонка обгортка над
[офіційним API](https://horoshop.notion.site/api-doc).

Команда запуску, яку треба прописати в конфіг MCP-клієнта:

```
npx -y github:ecomkit-com-ua/horoshop-mcp
```

Окремо нічого встановлювати не треба: `npx` сам завантажить репозиторій, збере його і запустить.
Потрібен Node.js 20 або новіший — перевір `node --version` перед налаштуванням.

## Крок 1. Збери дані в користувача

Потрібні три речі, і всі три ти маєш **отримати від користувача**:

- `HOROSHOP_DOMAIN` — домен магазину, наприклад `myshop.com.ua` (можна з `https://`)
- `HOROSHOP_LOGIN` — логін адміністратора
- `HOROSHOP_PASSWORD` — пароль адміністратора

Правила:

- Якщо бракує хоч одного значення — **зупинись і спитай користувача**. Не вигадуй домен, не
  підставляй приклади, не шукай пароль у файлах, змінних середовища чи менеджері паролів
  користувача.
- Horoshop не має API-ключів: авторизація йде звичайним логіном і паролем адміна.
- Порадь користувачу створити **окремого адміна саме для API**: в адмінпанелі
  **Налаштування → Адміни → додати адміністратора**. Так доступ можна відкликати одним рухом, не
  блокуючи собі вхід, і в логах видно, що робив саме інтеграційний доступ.

## Крок 2. Пропиши конфіг

Визнач, у якому клієнті ти працюєш, і додай блок у відповідний файл:

- **Claude Code** — `.mcp.json` у корені проєкту
- **Claude Desktop** — `claude_desktop_config.json`
  (macOS: `~/Library/Application Support/Claude/`, Windows: `%APPDATA%\Claude\`)
- **Cursor** — `~/.cursor/mcp.json` (або `.cursor/mcp.json` у корені проєкту)
- **Cline** — файл налаштувань MCP у сховищі розширення (`cline_mcp_settings.json`)

Блок для всіх однаковий:

```json
{
  "mcpServers": {
    "horoshop": {
      "command": "npx",
      "args": ["-y", "github:ecomkit-com-ua/horoshop-mcp"],
      "env": {
        "HOROSHOP_DOMAIN": "myshop.com.ua",
        "HOROSHOP_LOGIN": "api",
        "HOROSHOP_PASSWORD": "...",
        "HOROSHOP_READONLY": "1"
      }
    }
  }
}
```

Якщо файл уже існує — **додай ключ у наявний об'єкт `mcpServers`**, не перезаписуй файл цілком і
не чіпай інші сервери.

## Крок 3. Почни з режиму лише-читання

У блоці вище свідомо стоїть `HOROSHOP_READONLY: "1"`. У цьому режимі інструменти запису взагалі
не реєструються — перший запуск фізично не може нічого змінити в живому магазині.

Коли користувач перевірив, що все працює, і **сам просить** доступ на запис — прибери рядок
`HOROSHOP_READONLY` з конфіга і перезапусти клієнт. Не прибирай його на власний розсуд.

## Крок 4. Безпека

- Файл конфігурації містить пароль адміна відкритим текстом. Якщо це `.mcp.json` у git-репозиторії
  — додай `.mcp.json` у `.gitignore` і переконайся, що він не потрапив у коміт.
- Не друкуй пароль у відповідь користувачу, не пиши його в логи, не передавай нікуди, крім самого
  файлу конфігурації.
- Не комітай конфіг із паролем.

## Крок 5. Перевір

1. Попроси користувача перезапустити MCP-клієнт — без цього сервер не підхопиться.
2. Подивись список інструментів. Має бути **7** у режимі лише-читання
   (`horoshop_orders_list`, `horoshop_order_statuses`, `horoshop_products_export`,
   `horoshop_categories_export`, `horoshop_users_export`, `horoshop_store_reference`,
   `horoshop_call`) і **14**, якщо `HOROSHOP_READONLY` не заданий.
3. Зроби один нешкідливий читальний виклик — `horoshop_order_statuses` або
   `horoshop_store_reference`. Успішна відповідь означає, що логін і пароль правильні.

## Якщо щось не працює

- `Wrong login or password` — логін і пароль мають належати адміну магазину з Кроку 1, а не
  покупцю й не менеджеру без доступу до адмінки.
- `UNDEFINED_FUNCTION` — функція потребує Horoshop 4.0+ або модуля B2B. Це обмеження магазину, а
  не помилка конфігурації.
- Сервер не стартує, помилка про версію Node — потрібен Node.js 20 або новіший.
- Помилка про відсутні змінні середовища — перевір, що всі три обов'язкові ключі є в блоці `env`
  саме цього сервера, а не деінде у файлі.

## Змінні середовища повністю

Обов'язкові:

- `HOROSHOP_DOMAIN` — домен магазину
- `HOROSHOP_LOGIN` — логін адміна
- `HOROSHOP_PASSWORD` — пароль адміна

Необов'язкові:

- `HOROSHOP_READONLY=1` — сховати всі інструменти запису
- `HOROSHOP_TIMEOUT_MS` — таймаут запиту, за замовчуванням `60000`
- `HOROSHOP_MAX_RESPONSE_BYTES` — межа розміру відповіді, за замовчуванням `100000`
- `HOROSHOP_INSECURE_HTTP=1` — звертатися по `http` замість `https` (для тестових магазинів)

Повна документація — у [README](README.md).
